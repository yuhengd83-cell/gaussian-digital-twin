# v5.5.1 首屏 0% 修复版

## 为什么可能一直是 0%？

加载界面在 HTML 里默认显示 0%，但 JavaScript 核心模块如果未加载完成，页面不会走到模型下载。原 v5.5 新增 `./src/agv-route-editor.js` 依赖，若文件缺失（或外部 Three.js / Spark CDN 不通）就可能导致静态 0%。目前无法仅凭截图断言是哪种原因。

## v5.5.1 修复

- 将 AGV 路线模块嵌入 `agv-test.html`。现在即使误漏 `src/` 文件夹，测试页也不会因这个依赖缺失而停在 0%。
- 保留 `src/agv-route-editor.js` 作为独立模块源码及 Node 测试来源。
- 添加独立的启动诊断脚本：超过 12 秒未能运行主程序时，页面显示模型资源 HTTP 状态，并建议检查 F12 Console。
- 使用全新本地端口 **8096**、版本号 **5.5.1**，规避 8095 上旧服务器与缓存。
- `index.html` 保持 v5.4 Stable 原封不动。

## 推荐操作（重新解压完整版）

1. 将此完整版 ZIP 解压到一个全新文件夹，不要覆盖旧版。
2. 将你本机已经验证通过的 `splat.spz` 复制到 `models/splat.spz`。完整 ZIP **不包含用户模型**。
3. 双击 `start_agv_v55_1_fixed.bat`。
4. 浏览器应打开 `http://127.0.0.1:8096/agv-test.html?v=5.5.1`。
5. 12 秒后如果仍停留，将出现可见诊断信息。请把**该界面和 F12→Console 的红色报错**截图发回。

## 如果不想重新解压

只从补丁包取 `agv-test.html` 覆盖旧文件，再在旧 8095 端口打开：

`http://127.0.0.1:8095/agv-test.html?v=5.5.1`

此操作不改变 `models/splat.spz`、`viewer_config.json`、`index.html`。
